# Веб-панель AutoResearch в стилистике Альфа Хак

## 1. Что создаём

Локальную панель для запуска и наблюдения за нашим ML-агентом. Основной сценарий: загрузить задачу → задать бюджет → запустить исследование → увидеть эксперименты → скачать предсказания.

Первый этап — полностью кликабельный интерфейс с демонстрационными данными. Второй — подключение к настоящему harness. Интерфейс работает отдельно от конкурсного ZIP; solution.py сохраняет самостоятельность.

Название первой версии: AutoResearch, подпись — «AI-агент для разработки ML-моделей». Язык интерфейса — русский.

## 2. Визуальное направление

Берём оформление из оригинального ТЗ: яркий красный, насыщенный синий, лаймовые детали, крупная жирная типографика и геометрические акценты.

- Основной фон — светло-серый #F5F5F7, рабочие поверхности — белые, текст — #171717.
- Красный #F52C20 — основная кнопка и фирменные элементы; синий #0755FF — активный эксперимент и выделение информации.
- Лайм #C6EE26 — небольшие акценты на выбранном результате. Статусы всегда сопровождаются текстом и иконкой.
- Шрифт — локально поставляемый Manrope с кириллицей; числа метрик — одинаковой ширины.
- Крупные заголовки, тонкие разделители, умеренные скругления. Декоративная наклонная геометрия — только в шапке и пустых состояниях.
- Графики и таблицы занимают основное пространство. Объёмная графика с обложки не мешает работе с результатами.
- Основной размер — ноутбук 1440×900; корректная компоновка от 1280×720. На узких экранах колонки складываются, таблицы прокручиваются.

## 3. Экраны и взаимодействия

### История исследований — /runs

Слева постоянная навигация, сверху название и кнопка «Новое исследование».

Список запусков показывает задачу, тип, состояние, лучшую validation-метрику, изменение относительно baseline, время и дату. Фильтры: все, выполняются, завершены, остановлены, ошибки.

В пустом состоянии — две кнопки: «Создать исследование» и «Посмотреть демо».

### Новое исследование — /runs/new

Два шага:

1. Материалы: название, описание задачи текстом или task.md, четыре файла — train.csv, test.csv, data_dictionary.csv, sample_submission.csv. Для каждого файла — название, размер, состояние загрузки и возможность замены.
2. Ресурсы: время, токены и число потоков. Значения по умолчанию: 30 минут, 32 000 токенов, 4 потока. Дополнительные настройки раскрываются отдельно: seed, память, worker timeout и режим Qwen / Optuna / baseline.

Перед запуском — сводка выбранных параметров и доступности Qwen. Ключи вводить через браузер не требуется: сервер использует локальную конфигурацию.

### Исследование — /runs/:id

Главный экран для работы и защиты:

- Шапка: название задачи, модель Qwen, статус, время, действия.
- Полоса этапов: подготовка → baseline → исследования → финальное обучение → результат. Показываем текущий этап, без выдуманного процента готовности.
- Сводка: baseline, лучшая полная validation-метрика, дельта, завершённые эксперименты, оставшийся бюджет.
- График качества: baseline и результаты full-экспериментов; направление улучшения обозначено. Smoke не смешивается с full.
- Лента гипотез: какая ошибка замечена → что предложено → что фактически запущено → что измерено.
- Ресурсы: время и токены, отдельно показывается неопределённость usage.

Нажатие на эксперимент открывает боковую панель: родитель, гипотеза, параметры, изменения признаков, результат, ошибки и длительность. Предложенные и фактически исполненные параметры отображаются раздельно. Код — в сворачиваемом блоке.

Действия: «Прервать запуск», «Скачать текущий CSV», после завершения — «Скачать итоговый CSV» и «Скачать отчёт». Прерывание требует подтверждения и сохраняет уже существующий результат; новый refit после прерывания не обещаем.

Ошибки API, отклонение параметров и timeout показываются внутри соответствующей попытки. Существующий CSV остаётся видимым независимо от статуса исследования.

## 4. Реализация по этапам

### Этап A — отрисовка и кликабельный прототип

- Отдельный каталог web/: React, TypeScript, Vite; обычные CSS-переменные для темы, Recharts для графиков, Lucide для иконок.
- Реализовать три маршрута и общий слой доступа к данным, чтобы позже заменить демоисточник на API без переписывания экранов.
- Подготовить фиксированные сценарии: пустая история, загрузка файлов, выполняющийся запуск, улучшение, отсутствие улучшения, отказ Qwen, timeout и завершение с сохранённым baseline.
- Демо постоянно помечено «Демонстрационные данные». Проигрывание сценария не вызывает API Qwen и не запускает обучение.
- Добавить управление воспроизведением: старт, пауза, повтор. Это управление демонстрацией, а не обещание паузы реального ML-процесса.

### Этап B — подключение harness

- Отдельный локальный FastAPI-сервис в web_api/, со своими зависимостями; он не включается в конкурсный архив.
- Сервер запускает существующий solution.py отдельным процессом. Один активный ML-запуск; остальные исследования можно просматривать.
- Минимальный API: создание задачи с файлами, запуск, список и состояние исследований, детали эксперимента, прерывание, скачивание разрешённых артефактов.
- Обновление состояния — polling раз в две секунды, прекращается после завершения.
- Адаптер читает существующие отчёты и JSONL без изменения файлов. Незавершённую последнюю строку журнала временно пропускает; существующий восстанавливающий read_events() для просмотра не использует.
- Каждая задача получает отдельный каталог. Пути из загруженного описания проверяются и ограничиваются его файлами.
- Сервер доступен только через loopback; секреты и произвольные локальные пути в API не возвращаются. Запросы управления проверяются на допустимый Origin.
- Прерывание завершает дерево процессов и подтверждается наблюдаемым состоянием. После перезапуска панели статус сверяется с процессом и артефактами.
- Добавить единые команды локального запуска UI и API. Конкурсный packaging продолжает включать только существующее ядро.

## 5. Проверки и критерии готовности

Прототип готов, когда можно пройти весь сценарий от создания задачи до результата, открыть каждый эксперимент и воспроизвести все состояния. Нет кнопок, которые выглядят рабочими, но ничего не делают. Проверены клавиатурная навигация, читаемость и отсутствие наложений на целевых размерах экрана.

Подключённая версия готова, когда:

- реальная задача запускается из браузера через существующий CLI;
- метрики и параметры совпадают с артефактами harness;
- перезагрузка страницы не теряет исследование;
- повторное нажатие не создаёт второй процесс;
- отказ API и прерывание сохраняют доступный CSV;
- скачивается именно файл выбранного запуска;
- веб-просмотр не изменяет журналы;
- frontend/API не попадают в конкурсный ZIP.

Приёмку веб-интеграции сначала проводить с fake LLM и небольшими данными. Live-проверку совмещать с запланированной проверкой целевой Qwen, без дополнительных дорогостоящих прогонов.

По умолчанию в первую версию не входят аккаунты, облачное размещение, параллельные обучения, чат с агентом и ручное редактирование гипотез во время запуска.
