# План реализации

Этапы выполняются последовательно. Каждый заканчивается проверяемым результатом; следующий этап начинается после его проверки. Подготовительный коммит отделён от реализации агента.

## 0. Подготовка — текущий этап

- [x] Сохранить ТЗ, исследование и источники организаторов.
- [x] Создать Clean Architecture, правила импортов и AGENTS.md.
- [x] Зафиксировать Python, зависимости и lock-файл; создать локальное окружение.
- [x] Описать сценарии, контракты и этапы реализации.
- [x] Пройти проверки окружения, стиля, типов и архитектуры.

Публикация этапа: отдельный коммит и push без агентного соавторства; факт публикации проверяется по совпадению локального HEAD и удалённой ветки.

Готовность: удалённая ветка содержит scaffold и план, локальное окружение воспроизводится через `make setup`. Исследовательская логика пока отсутствует.

Проверено локально на macOS arm64: `make check`, `uv pip check`, загрузка Qwen SDK/ML-библиотек/AutoGluon, соответствие 18 runtime-требований списку организаторов, `python -S solution.py --help`. Python 3.12.12, uv 0.9.17. Linux-проверка и обучение относятся к следующим этапам; тестов поведения пока нет.

Готовность: один вызов solution.py на каждой публичной задаче создаёт корректный CSV, использует фиксированный split, не требует установки/сети во время работы модели. Это ещё не агент, но сквозной путь уже работает.

Готовность: серия экспериментов переживает перезапуск; следующая сессия видит прошлые неудачи и работает в ограниченном контексте независимо от длины полного журнала.

## 5. Исследование по ошибкам

- [ ] Реализовать отчёт по классам/матрицу ошибок и регрессионные ошибки по устойчивым сегментам с достаточным support.
- [ ] Вычислять изменения относительно parent на тех же объектах; отделять наблюдения от интерпретаций.
- [ ] Реализовать выбор следующего направления и parent, ветвление по гипотезам, сохранение полезных альтернатив.
- [ ] Добавить ограниченный Optuna-поиск внутри эксперимента и AutoGluon-кандидат с явным разрешённым набором моделей.
- [ ] Проверить хотя бы несколько содержательно разных гипотез, влияние на общую метрику и целевые сегменты; не считать smoke-метрики полноценным результатом.

Готовность: журнал позволяет показать конкретную цепочку «ошибка → гипотеза → изменение → измеренный эффект». Отсутствие улучшения тоже корректный результат, а не повод менять оценщик.
