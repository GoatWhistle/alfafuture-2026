# Задание организаторов

Текст кейса «AI-агент для разработки ML-моделей» хакатона Альфа-Банка. Интерфейс запуска — [baseline.py](baseline.py), разрешённые библиотеки — [requirements.txt](requirements.txt).

Секция: AI-агент для разработки ML-моделей; Tур: Онлайн тур

Создайте AI-агента, который самостоятельно решает задачи машинного обучения: от чтения условия до готового файла с предсказаниями. Для этого:
Научите агента анализировать текстовое описание задачи, изучать структуру входных данных, определять тип ML-задачи и требования к результату.
Автоматизируйте построение решения, где агент сам выбирает подход, генерирует и запускает код, обучает модель, оценивает качество на собственной валидации и формирует итоговые предсказания.
Добавьте цикл AutoResearch. Агент анализирует результаты экспериментов, формулирует гипотезы для улучшения модели, проверяет их и выбирает лучший вариант решения.
Обеспечьте универсальность. Один и тот же код должен решать разные задачи, включая классификацию и регрессию и другие задачи машинного обучения, без ручной настройки под конкретный датасет.
Отправьте агента на платформу. Решение проверяется на двух публичных задачах, а итоговый результат определяется на двух скрытых, которые агент увидит впервые.
Формат сдачи

На платформу загружается ZIP-архив с решением. В корне архива должен лежать файл solution.py — единая точка входа для запуска агента. Логику можно распределить по нескольким модулям внутри того же архива: solution.py импортирует их и вызывает нужный код. Платформа запускает решение в Docker-контейнере.

Переменные окружения, интерфейс запуска и формат вывода зафиксированы в baseline.py. Решение должно строго соблюдать этот интерфейс, иначе платформа не сможет его проверить.

Важно! Число сабмитов в день на команду ограничивается 3. Количество сабмитов обновляется в 00:00 по МСК каждый день.

Кейс, baseline.py и доступные библиотеки requirements.txt вы найдете ниже.
Как подготовить и загрузить решение

Что положить в ZIP

Все файлы должны лежать в корне архива, без папок:

solution.py — точка входа;
requirements.txt — предоставленный список зависимостей;
дополнительные .py-модули, если они нужны.
В каталог задачи копируются только корневые .py-файлы и requirements.txt. Вложенные папки и остальные файлы — данные, .whl, конфиги — не копируются. Если необходимый модуль находится в подпапке, при запуске он будет недоступен и решение может получить 0 баллов.

Сторонние пакеты и .whl добавлять нельзя. Зависимости устанавливает платформа из корневого requirements.txt. Запуск собственного pip из solution.py недоступен.

Как запускается решение

Платформа копирует файлы в каталог задачи и выполняет команду:

python3 solution.py task.md
Скрипт работает в одной папке с task.md. Итоговый submission.csv сохраняйте туда же.

Промежуточные файлы можно создавать в каталоге задачи, в его подкаталогах и в /tmp. Запрет на папки касается только загружаемого ZIP.

Лимиты

Размер ZIP — до 100 МБ.
Ресурсы на один запуск задачи — 8 CPU и 32 ГБ RAM.
Время работы — до 3 часов.
Как проходит проверка в Boosters

Boosters — система автоматической проверки решений. После загрузки файл проходит проверку загрузки, передаётся в Boosters и ставится в очередь на проверку.

Статус «Решение находится на проверке» означает, что решение принято в очередь. Это ещё не результат проверки.

После успешной проверки появится сообщение «Точность вычисления: …» с полученной оценкой. Если отправить или проверить решение не удалось, появится сообщение об ошибке.

Ошибки загрузки и отправки

Сообщение	Что делать
«Выберите файл решения»	Прикрепите ZIP с решением.
«Допустимы только файлы CSV или ZIP»	Для трека AutoML загрузите ZIP, подготовленный по инструкции выше.
«Файл пустой. Загрузите файл с решением»	Проверьте содержимое архива и загрузите его повторно.
«Размер файла не должен превышать 128 мегабайт» или «Файл решения слишком большой»	Уменьшите архив. Для трека AutoML действует лимит 100 МБ, даже если загрузчик указывает больший технический порог.
«В файле решения ошибки: …»	Исправьте ошибки, перечисленные в сообщении.
«Не удалось загрузить файл», «Не удалось получить публичную ссылку на файл решения» или «Не удалось отправить решение»	Попробуйте загрузить решение ещё раз. Если ошибка повторяется, обратитесь к организаторам.
«Задание ещё готовится», «Команда ещё подключается к системе заданий» или «Ваш профиль ещё синхронизируется»	Подождите и отправьте файл ещё раз.
«Вы исчерпали лимит попыток»	Лимит отправок исчерпан. Уточните у организаторов условия дальнейшей отправки.
«Команда не допущена к этому туру», «Команда дисквалифицирована» или «Вы не состоите в этой команде»	Если считаете сообщение ошибочным, обратитесь к организаторам для проверки статуса команды или участника.
Ошибки во время проверки

Сообщение	Что означает и что проверить
«Ошибка формата данных»	Система обнаружила ошибку формата. Проверьте соответствие файлов требованиям задачи.
«Превышено время обработки решения»	Решение не уложилось в отведённое время. Проверьте длительность работы скрипта, включая обращения к модели.
«Не хватает данных в решении»	Для проверки не хватает необходимых данных. Проверьте, что скрипт формирует все требуемые результаты.
«Не хватает данных в решении: отсутствует файл …»	Проверьте, создаётся ли указанный файл и сохраняется ли он в нужном каталоге. Итоговый submission.csv должен находиться рядом с task.md.
«Ошибка скоринга сабмита. Попробуйте позже»	Система не смогла завершить оценку. Попробуйте позже; если ошибка повторяется, обратитесь к организаторам.
При обращении к организаторам приложите текст ошибки или скриншот и время отправки решения. Подробные технические логи доступны только администраторам и могут не отображаться в вашем интерфейсе
