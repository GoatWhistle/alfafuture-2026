# Веб-панель AutoResearch

Локальная панель для запуска и наблюдения за ML-агентом. Не входит в конкурсный ZIP:
`scripts/build_submission.py` упаковывает только `solution.py` и `ml_harness/`.

Инструкция для сокомандников с клонированием репозитория и подготовкой окружения —
[быстрый старт в основном README](../README.md#веб-панель-быстрый-старт-для-команды).
Все команды ниже выполняются из корня репозитория.

## Только демо

Нужны Node.js/npm. `.env`, Python и датасеты не требуются:

```bash
npm ci --prefix web
make web-demo
```

Адрес: <http://127.0.0.1:5173>. Все исследования демонстрационные; обучения и
вызовов Qwen нет.

## Подключённая панель

Нужны окружение harness (`make setup`), Node.js/npm и зависимости веб-панели.
Для одного сервера с интерфейсом и API:

```bash
make web-setup
(cd web && VITE_DATA_SOURCE=api npm run build)
make web-api
```

Адрес: <http://127.0.0.1:8765>. Этот вариант не использует порт 5173.
Для Qwen заполните `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL` в
корневом `.env` по `.env.example` либо задайте их в окружении сервера.
Чужой полный `.env` не нужен; используются выданные команде реквизиты.
Общий ключ означает общую квоту. Baseline/Optuna на однозначно описанной задаче
можно запускать без ключей.

Данные исследований API хранит в `runs/web/<id>/` (игнорируется Git).
Четыре CSV и описание загружаются через мастер создания исследования; сами датасеты
не входят в репозиторий. Ключи в браузер не передаются.
Доступ только с текущего компьютера через `127.0.0.1`, один активный ML-запуск.
Перед остановкой API через `Ctrl+C` прервите ненужное обучение кнопкой в интерфейсе:
остановка API сама по себе не останавливает дочерний ML-процесс.

## Разработка с Vite

После `make setup` и `make web-setup` в первом терминале выполните `make web-api`,
во втором — `make web-ui`. Откройте <http://127.0.0.1:5173>.
`web-demo` и `web-ui` используют один порт: запускайте только один из них.
Если порт занят, используйте сборку на 8765 из предыдущего раздела.

```bash
make web-setup      # npm ci + зависимости web_api
make web-demo       # только интерфейс, демонстрационные данные (http://127.0.0.1:5173)
make web-api        # API на 127.0.0.1:8765, запускает solution.py
make web-ui         # интерфейс с подключением к API (запускать вместе с web-api)
make web-check      # сборка, тесты интерфейса и API
```

`make web-check` создаёт сборку в режиме демо. Перед запуском собранной подключённой
панели повторите сборку с `VITE_DATA_SOURCE=api`, как показано выше.

## Проверки в браузере (e2e)

Скрипты в `web/e2e/` управляют Chrome через DevTools Protocol без сторонних пакетов
(путь к Chrome можно задать через `CHROME`). `<work>` — любой временный каталог.

```bash
node web/e2e/make-data.mjs <work>               # синтетическая задача в <work>/syn
make web-demo & node web/e2e/demo.mjs <work>     # демо: клавиатура, диалоги, состояния, наложения

# подключённая версия с fake LLM (без обращений к Qwen):
python web_api/tests/fake_llm.py 8799 <work>/llm.log &
(cd web_api && OPENAI_BASE_URL=http://127.0.0.1:8799/v1 OPENAI_API_KEY=fake \
  OPENAI_MODEL=fake-qwen WEB_API_RUNS=<work>/runs-web uv run python -m app.main) &
make web-ui & node web/e2e/api.mjs <work>
```
