# AutoML-агент (хакатон Альфа-Банка)

Агент решает табличную ML-задачу end-to-end: `python3 solution.py task.md` → `submission.csv`.

## Стратегия на максимальный балл

Балл = нормировка метрики против бейзлайна организаторов, хуже бейзлайна — 0.
Отсюда два приоритета: **никогда не падать** (упавший запуск = 0) и **выжать метрику**.

Каскад (каждая ступень перезаписывает `submission.csv`, файл существует с первой минуты):

0. **constant** — медиана/мода: страховка формата;
1. **quick_lgbm** (~минуты) — LightGBM с early stopping: уже сильнее типового бейзлайна;
1.5. **AutoEDA** (≤20 мин, `AGENT_AUTOEDA_SEC`; при нехватке времени пропускается):
   детекторы находят зависимости → гипотезы оформляются декларативными спеками
   DSL → единый валидатор принимает только то, что улучшает модель на фолдах,
   похожих на тест. Код признаков пишется один раз (`fe_dsl.py`), LLM и детекторы
   выдают только спеки.
   - `fe_dsl.py` — операции `group_stat` (таргет cross-fitted / признак), `group_dev`,
     `lag` (история объекта в прошлых периодах), `ratio/diff/prod`, `agg_cols`,
     `log/rank`, `count_enc`, `missing_ind`, `bin`, `interaction`, `knn_target`, `flag`, `drop`;
     `as_category` (целочисленный код как категория), `missing_count`, `date_parts`,
     `cyclic` (sin/cos периода); `group_stat` по таргету со сглаживанием (`smooth`)
     и переходом к общим ключам (`fallback`) для редких/неизвестных групп;
     модельные операции `segment_model` (отдельные модели на сегменты-режимы) и
     `objective` (huber/l1/fair для тяжёлого хвоста ошибок регрессии);
     исполнение fit → apply: на валидации fit = train фолда, в финале fit = весь train;
   - `eda_detectors.py` — 11 детекторов, у каждой спеки непрерывный `prior` (порядок
     оценки): **entities** (beam-поиск квази-ID объекта), **temporal** (период + лаги
     таргета по каждому кандидату ключа), **residuals** (ω² остатков OOF по колонкам,
     парам и путаемым парам классов), **categoricals**, **homogeneous** (группы имён
     `*_min/_avg/_max`, единицы словаря), **neighbors** (дубли, kNN-таргет, флаг
     label_copy, конфликты меток по классам), **segments** (естественные разделители —
     ноль, пропуск, уровни; смена корреляций и смещение остатков внутри сегмента,
     эквивалентные разбиения схлопываются), **tail** (доля ошибки в худших строках и
     что их объединяет), **missingness**, **transforms**, **shift** (adversarial validation);
   - Qwen, раунд 1 (`task_profile.llm_propose_specs`): 4 тематических промпта
     параллельно — время и объекты, сегменты, ошибки (хвост, перестановочная важность
     против корреляции, конфликты меток), семантика словаря; у каждого свои факты и
     список уже запланированных гипотез. Идёт в фоне, пока валидатор проверяет спеки
     детекторов. Раунд 2 (`llm_refine_specs`): Qwen видит итоги этапа A (дельты, что
     прошло) и развивает работающие направления. Все спеки — в тот же валидатор;
   - `fe_search.py` — фолды под тест (период → train на прошлом, val на последних
     периодах; новые объекты в test → GroupKFold; иначе (Stratified)KFold),
     детерминированный LightGBM; порог прироста калибруется по null-спекам
     (перемешанные копии топ-признаков); этап A — каждая спека против базы, этап B —
     жадный forward-отбор; признак с подозрительно идеальной метрикой отклоняется.
     Каждая спека попадает в журнал экспериментов. Принятые `segment_model`/`objective`
     переносятся в k-fold LightGBM для бленда, индикатор сегмента — признаком в AutoGluon;
2. **k-fold LightGBM** (`quick_oof`) на фолдах схемы cv — OOF-база и мерило
   стоимости для пула;
3. **пул рецептов** (`pool.py`, `AGENT_POOL_SHARE`=30% остатка): каждый рецепт —
   k-fold на тех же фолдах + frozen refit на всём train; допуск по профилю и
   прогнозу стоимости (кратно k-fold LightGBM), пропуск/сбой — в журнал:
   - регрессия: `log1p`/`sqrt` таргета при неотрицательном асимметричном таргете
     (обратное преобразование ровно один раз), Tweedie и двухчастная модель
     P(y>0)·E[y|y>0] при ≥10% нулей, `l1` под MAE, прогноз изменения от последнего
     таргета объекта (`delta`, при temporal-схеме и принятом `lag(target)`);
   - классификация Macro F1/F1: ранняя остановка LightGBM по метрике задачи;
   - ExtraTrees (bootstrap до 60k строк), XGBoost (hist, категории), регуляризованный
     LightGBM, CatBoost (TotalF1:Macro / AUC для остановки, Balanced для macro-метрик) —
     в порядке ценности на единицу стоимости; затем 2 seed лучшего рецепта и
     4 конфигурации LightGBM из каталога регуляризации/сэмплирования;
   - регрессия: если log1p/sqrt обошёл исходную шкалу, остальные семейства пула и
     AutoGluon обучаются в выигравшей шкале;
   - свободный текст (несколько слов, высокая уникальность): TF-IDF слов и
     символов + Ridge/LogisticRegression, матрица разреженная;
   после пула — промежуточный выбор и запись сабмита;
4. **autogluon** (остаток) — `TabularPredictor` c presets по бюджету времени
   (`best_quality`/`high_quality`/`good_quality`), eval_metric из профиля задачи;
5. **AutoResearch-постпроцессинг** — гипотезы принимаются только при улучшении OOF:
   - жадный ансамбль (Caruana, с возвращением) по всем оценённым кандидатам:
     модель вне двух лидеров входит, если улучшает смесь; дубли прогнозов пропускаются;
   - общие OOF-строки делятся на development (70%: состав/веса ансамбля, классовые
     множители) и control (30%, по группам при group-схеме) — аудит: смесь и
     множители принимаются, только если не хуже на control;
   - log loss: Platt (бинарная) / temperature scaling (мультикласс) по OOF,
     прирост проверяется 2-fold cross-fit; вероятности AutoGluon не перекалибруются;
   - классификация с macro-метрикой: координатный подбор классовых множителей
     вероятностей (сильно поднимает Macro F1 на дисбалансе);
   - регрессия: клиппинг предсказаний к диапазону таргета в train;
   - выбор источника, α бленда, веса классов и клиппинг — на общих OOF-строках
     кандидатов одной схемы валидации (см. «Независимая валидация»);
   - `label_copy_dups` (флаг детектора neighbors, классификация): метки точных дублей
     train без конфликта переносятся в test; ворота — LOO на train-дублях против OOF модели.

## Профиль задачи (универсальность для private-задач)

- id и целевые колонки — из `sample_submission.csv` (истина про формат);
- кросс-чек ролей по `data_dictionary.csv`;
- пути к данным — из текста task.md, иначе поиск рядом и рекурсивно;
- тип задачи и метрика — **LLM (Qwen через `OPENAI_*`) читает task.md**
  (до 2 попыток, строгий JSON); жёсткие факты из данных (dtype таргета,
  число уникальных) отсекают невозможные ответы LLM;
- без LLM: метрика — первое упоминание в тексте задачи, «регрессия» в тексте
  оставляет регрессией таргет с малым числом целых значений; последний рубеж —
  дефолты: регрессия → RMSE, мультикласс → Macro F1, бинарная → F1/accuracy;
- тип, метрика и формат вывода считаются отдельно для каждого таргета
  (`prof["per_target"]`); признаки AutoEDA одного таргета не переходят на другой;
- RMSLE → обучение на `log1p(y)`, оценка всех кандидатов — настоящий RMSLE;
- положительный класс бинарной задачи — `models.positive_label` (1/True,
  словарь yes/fraud/bad…, иначе последняя метка): одно правило для F1/AUC,
  весов классов и выходной вероятности;
- вывод вероятностей: бинарная задача с log_loss/roc_auc (заглушки sample
  не важны) или float-значения sample вне меток; колонки sample, которых нет
  в train, сопоставляются классам таргета по имени (`A`, `target_A`, `p_A`),
  иначе по порядку.

## Независимая валидация

Схема, выбранная AutoEDA (`fe_search.build_folds` → `prof["cv"]`: temporal по
периоду, group по ключу объекта или kfold), действует до конца конвейера:

- `models.outer_folds` — внешние фолды по той же схеме для k-fold LightGBM,
  quick-сравнения и AutoGluon; temporal: train — только прошлые периоды;
- ранняя остановка — на отдельной части train фолда (`es_split`), не на оцениваемом фолде;
- признаки из таргета (`group_stat`/`lag` по таргету, `knn_target`) не пишутся
  в train: `models.target_features` строит их заново в каждом фолде (fit = train
  фолда), внутренний cross-fit (`fe_dsl.inner_splits`) тоже соблюдает схему —
  только прошлые периоды, чужие группы. AutoGluon получает их только при temporal
  (признаки строятся по прошлому); при kfold/group бэггинг протёк бы через них;
- AutoGluon бэггит по тем же фолдам (`groups`); при temporal — holdout-fit на
  прошлом с оценкой на последнем периоде, затем fit на всём train для test;
- OOF кандидатов сопоставляются по индексам строк train и порядку классов
  (`solution.align_candidates`); строки без OOF исключаются, расхождение
  таргета — ошибка;
- test предсказывает модель, обученная на всём размеченном train.

## Журнал экспериментов

`experiments.jsonl` рядом с task.md: строка на каждый эксперимент (гипотеза,
таргет, метрика, схема проверки, скор, длительность, решение, причина отказа
или ошибки), дописывается сразу — доступен после сбоя.

## Точные ключи

`eda_probe.normalize_keys`: целые — десятичной записью без float (большие
int64 не склеиваются), 1942 и 1942.0 совпадают, пропуск — отдельный уровень,
компоненты составного ключа хэшируются раздельно. Перенос меток дублей
сверяет точные строки ключей (`row_key_strings`), а не хэши.

## Запись результата

`write_submission` собирает файл по контракту (колонки и порядок sample,
id и порядок строк test, конечность, вероятности в [0, 1], сумма строки = 1),
пишет во временный файл и заменяет `submission.csv` через `os.replace`.
Не прошедшая проверку версия не пишется: остаётся предыдущий валидный файл,
предсказания в памяти откатываются. Неоценённый кандидат (метрика не
посчитана) не участвует в выборе; целевая метрика не подменяется accuracy.

Тесты (синтетика, без LLM; `test_autogluon.py` пропускается без autogluon —
для него добавить `--with "autogluon.tabular[lightgbm]==1.3.1" --with typing_extensions`):

```bash
cd solution && uvx --python 3.12 --with numpy==1.26.4 --with pandas==2.2.3 \
  --with scikit-learn==1.5.2 --with lightgbm==4.6.0 --with scipy==1.12.0 pytest tests -q
```

## Тайм-менеджмент

Бюджет 3 ч (`AGENT_TIME_LIMIT_SEC` для локальных тестов), запас 7 мин
(`AGENT_SAFETY_SEC`) + резерв 8 мин на predict (`AGENT_PREDICT_RESERVE_SEC`).
Каждый таргет работает до абсолютного времени окончания (`solve_target`:
`t_end`), этапы получают остаток от него. Ограничители:

- сторожевой поток (`agent_utils.start_watchdog`) за `AGENT_HARD_MARGIN_SEC`
  (2 мин) до лимита убивает дочерние процессы и завершает процесс с кодом 0 —
  на диске остаётся последний валидный `submission.csv`;
- AutoEDA — под `time_limit` (SIGALRM, бюджет × 1.25 + 60 с) на копии профиля;
  тяжёлые этапы остаются в главном потоке: LightGBM в рабочем потоке в 2,5–8
  раз медленнее из-за пулов OpenMP;
- LightGBM — callback `time_guard` по дедлайну (quick, k-fold, валидатор AutoEDA);
- LLM — каждый вызов ограничен по времени в daemon-потоке;
- в конце `os._exit` после остановки дочерних процессов: фоновые потоки не держат процесс;
- CPU — `available_cpus()`: affinity и квота cgroup (`AGENT_N_CPUS` — вручную).
AutoGluon получает остаток. Мульти-таргет — бюджет каждого таргета = фактический
остаток времени / число оставшихся таргетов.

## Сборка ZIP для платформы

Все файлы в корне архива, без папок:

```bash
cd solution && zip -j ../solution.zip solution.py task_profile.py models.py agent_utils.py eda_probe.py \
  fe_dsl.py fe_search.py eda_detectors.py pool.py requirements.txt
```

## Локальный тест

```bash
AGENT_TIME_LIMIT_SEC=900 AGENT_SAFETY_SEC=60 AGENT_PREDICT_RESERVE_SEC=120 \
  python3 solution.py /path/to/task.md
```
